# 核验标准

## 什么算「官方」

满足下面**任意一条**即可：

- **A. 厂商自有域名**：文档页在厂商自己的域名下，例如 `developer.amap.com`、`open.dingtalk.com`。
- **B. 厂商官方 GitHub 组织**：仓库属于厂商的官方组织，并且有互相印证：组织主页链接到厂商官网，或厂商官网、文档链接到这个仓库。
- **C. 第三方平台加官方背书**：托管在第三方平台（如 skillhub.cn、npm、ModelScope），但厂商的官方渠道（官网、官方公众号、官方 X 或微博账号）发布或链接了它。

都不满足就不收录：标 `rejected`，在 `rejectedReason` 写明原因。常见情况有个人或社区封装、逆向接口、只是「兼容」某服务的第三方工具。

## 核验时要填什么

把 `status` 改成 `verified`，然后检查并补全：

| 字段 | 怎么定 |
| :-- | :-- |
| `evidence.url` | A：文档页本身；B：厂商官网上链接到仓库的那一页；C：官方公告 |
| `evidence.checkedAt` | 核验当天 |
| `evidence.note` | 可选，比如「开放平台文档」「官方组织 alibaba-flyai，由飞猪官网链接」 |
| `types` | 以文档为准：真的提供 MCP Server 才写 `mcp`，有 Skill 文件才写 `skill`，有命令行工具才写 `cli` |
| `access` | 文档写明的门槛，比如要申请 Key、要开会员、要装客户端 |
| `risk` | `read`：只能查询；`write`：能创建或修改数据（发消息、写文档、管理云资源）；`payment`：能下单、付款、转账。跨多级时取最高一级 |
| `install.mcp` | 只有文档给出了端点或启动命令才填。Key 等写成 `<你的XXKey>` 这样的占位符 |
| `summary` | 对照文档修正，不超过 60 字 |
| `url` | 换成最直接的官方入口；原来的跳转链接或短链要替换掉 |

## 复核

- 已核验的条目，超过 180 天要复核一次。
- 链接检查报告失效时，先人工打开确认：有些国内网站会拦截海外机器访问，这种情况不算失效。
- 服务下线了就标 `rejected`，`rejectedReason` 写「已下线（日期）」。
